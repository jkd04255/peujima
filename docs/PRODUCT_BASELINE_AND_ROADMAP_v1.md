## 서비스 가설(검증 필요)
반려동물 보호자는 증상/진료과 기준으로 적절한 병원을 비교하고, 의료진과 예약 가능 시간을 확인한 뒤, 보험 관련 조건을 사전에 검토하고 싶다.
현재 서비스 가설은 실제 보호자 또는 병원 인터뷰로 검증되지 않았다.

## v0.5.2 기준선
- 공개 시연 주소: https://jkd04255.github.io/peujima/

- 의사 다수인 예제 병원의 수의사 선택, 7일 예약 타임라인, '기타' 진료 내용 직접입력.
- 시연용 예약 완료 카드와 보험 페이지 이동(자동 이동 없음).

**확정된 사실과 미검증 주장을 구별한다.** '예약 완료'는 UI 흐름 시연일 뿐 실제 병원 접수는 없다. 병원명/의사/시간/보험 조건 모두 실제 정보로 취급하면 안 된다.

## Sprint 00 — 기획 정렬(첫 공식 주기)
목표: 기존 화면을 뒤엎지 않고 다음 기능을 논리적으로 기획·검증할 수 있는 기준 확보.
예상 단위: 1주(제안, 실제 일정 확정 아님).

### 완료 조건
- [ ] 사용자 가치/핵심 대상/주요 불편을 정의하고 PO 승인 받기
- [ ] 현재 기능 목록과 위험 가설 확정
- [ ] 예약 전체 User Journey와 예외 상태(선택 전, 슬롯 없음, 취소, 기타 입력, 완료/보험 이동) 설계
- [ ] 최우선 기능 1건을 Feature Spec 형태로 작성하고 인수기준 확정
- [ ] 기능 변경 없이 프로세스·기획 문서부터 검토 완료

### 시작 전에 확인할 사항(기본 가정, 사용자가 바꿀 수 있음)
- 1차 고객은 반려동물 보호자(강아지·고양이 우선, 특수동물은 전체 모드).
- 1차 비즈니스 모델은 검증하지 않은 상태이며, 현재 제휴/수수료/광고 수익화의 확정은 없음.
- 1차 범위는 웹 정적 프로토타입, 백엔드는 아직 추가하지 않음.
- 첫 개선 후보는 '병원 상세보기'지만, 우선순위와 화면은 조사·명세 승인 후 결정.

## 베타 전환 게이트(향후 별도 의사결정)
- 실제 병원과 데이터 사용 및 예약 운영에 관한 협의/승인
- 일정 동시성·취소·병원 운영자 정정 등 예약 생명주기 완성
- 필요한 개인정보 처리 근거와 고지, 접근제어, 보관·삭제 정책 검토
- 보험 조건은 출처·상품 차이·면책·검증일·유의문구를 명시
- 일반 사용자 대상 접근성·모바일·정확성 테스트, 오류 대응과 롤백 계획

이 기준을 충족하지 않는 현재 배포는 '공개된 시연 페이지'이지 실제 운영 서비스가 아니다.
