# PJM-034 · 모바일 보험 결과 진입 위치와 키보드 포커스

기준선: PJM-033 PR #28 병합 `89fcbe9`, 사용자 수동 Pages 릴리스 #22 (`89fcbe9`; build/deploy 성공). 개선 유형: 국소 모바일 UI/UX.

## 사용성 문제

보험 상품 1개와 치료 항목 1개를 고른 뒤 `보장 내용 확인하기`를 누르면 긴 진료 세부 목록과 출처 안내가 생성됩니다. 기존 동작 `scrollIntoView({block:"nearest"})`는 길이가 뷰포트보다 큰 결과의 **첫머리가 항상 보이도록 보장하지 않으며**, 스크린리더·키보드 포커스는 버튼에 남았습니다. 사용자가 답변의 시작점을 놓칠 수 있습니다.

## 범위 및 구현

- 버튼을 실제로 눌렀을 때 결과 제목 `h3`에만 일시적 `tabindex=-1`와 프로그래밍 포커스를 부여합니다. 결과 제목을 추가 탭 순서에 넣지 않습니다.
- 화면 폭 850px 이하에서는 새 결과를 `block:start`로 위치시키고, 고정 메뉴(높이 69px)와 겹치지 않도록 86px 스크롤 여백을 둡니다. 그보다 큰 화면에서는 기존 `block:nearest` 동작을 유지합니다.
- 사용자 OS의 `prefers-reduced-motion`이 설정된 경우 부드러운 스크롤 애니메이션 대신 기본 즉시 동작을 사용합니다.
- 폼 `change`에서는 기존처럼 오래된 결과를 지우기만 하고 강제 포커스/자동 스크롤을 실행하지 않습니다.
- 재료 이미지·브랜드·색상·사진·병원·예약·지도·52개 진료 주제·235개 추정 비용·정부 공개 중간값·보험 보장/가상 예시·단일 하단 출처 안내를 변경하지 않습니다. 새 입력/버튼/설명 문구도 추가하지 않습니다.

## 인수 기준

1. 320/390/768px Chromium 및 390px WebKit에서 결과 제출 시 제목이 `document.activeElement`가 되고, 결과 상단이 sticky header 아래 2~45px 범위에 위치합니다.
2. 1440px Chromium에서 기존 큰 화면의 `nearest` 스크롤 방식은 유지합니다. 키보드 Enter 제출도 제목으로 포커스합니다.
3. 기존 보험·진료를 바꾸면 예전 결과가 즉시 삭제되며 새로 제출하기 전까지 재표시하지 않습니다.
4. PJM-011/012/013/014 및 보험 PJM-019~033 Chromium/WebKit/axe, 지도·예약, 정적 빌드 전체 회귀가 성공해야 합니다.
5. 실제 iPhone Safari 및 Instagram 인앱 브라우저의 스크롤 동작은 별도 실기기 검증이 필요합니다.
