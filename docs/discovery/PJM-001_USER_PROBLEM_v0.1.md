## 1. G0 의사결정 기록
- **G0-001 — 승인(2026-11-07):** 1차 고객은 반려동물 보호자이며 동물병원은 향후 제휴·운영 파트너다.
- 강아지/고양이를 먼저 지원하고 전체 모드에서 기타 반려동물을 다루는 시연 화면을 유지한다.
- G0 승인은 고객 역할에 대한 동의이며 문제의 빈도·시장성·다음 기능 범위(G1)를 승인한 것은 아니다.

## 2. 문제 정의 (미검증)
반려동물 보호자가 병원을 찾을 때 종·진료 분야·운영일·담당 수의사·예약 가능 시간 등 여러 조건을 따로 확인해야 할 가능성이 있다. 이 과정에서 적절한 병원을 선택하기까지 탐색이 길어지고, 실제 예약 가능 여부나 보험 약관을 오해할 위험이 있다.

**도전 질문 (How Might We):** 보호자가 신뢰 가능한 병원 정보를 확인하고, 자신에게 맞는 의료진과 시간을 선택하며, 실제 접수 상태와 보험 안내의 한계를 명확히 이해하게 하려면 어떻게 해야 할까?

## 3. 1차 사용자 및 보조 이해관계자

| 구분 | 잠정 상황 | 목표 | 주의점 |
| --- | --- | --- | --- |
| 보호자 A: 처음 방문 | 반려동물 증상에 어떤 분야가 맞는지 확신이 없는 보호자 | 진료 범위와 병원 차이를 이해하고 후보를 좁히기 | 증상 기반 자동 진단·응급도 판정은 제공하지 않음 |
| 보호자 B: 일정 제약 | 직장/학업/이동 때문에 가능한 진료 시간을 빠르게 알아봐야 하는 보호자 | 담당 수의사별 7일 시간표를 한눈에 비교 | 시연용 슬롯을 실제 가용 일정으로 오해하지 않도록 함 |
| 보호자 C: 보험 가입 | 진료 전에 가입 상품의 보장 조건을 확인하려는 보호자 | 확인할 약관·면책 조건 이해 | 보험금 지급 또는 적용 여부를 단정하지 않음 |
| 병원 파트너(미연결) | 예약·의료진·휴무 정보를 제공해야 하는 병원 관계자 | 병원의 통제 하에 정확한 일정 공개·변경 | 실제 업무 프로세스와 API 접근 범위는 미확정 |

위 유형은 **프로토 페르소나**다. 조사로 실제 존재 빈도를 확인해야 한다.

## 4. 검증할 Job-to-be-Done / 핵심 가설

| ID | 사용자의 할 일 | 가설 | 확인 방법 |
| --- | --- | --- | --- |
| H-01 | 내 아이의 종·진료 분야에 맞는 병원 찾기 | 단순 거리순보다 진료 분야/반려동물 종류 필터가 중요하다 | 최근 병원 탐색 경험·선택 기준 인터뷰 |
| H-02 | 내 일정에 맞춰 예약하기 | 병원마다 연락해서 가능한 날짜/수의사를 묻는 수고를 줄이고 싶다 | 실제 예약 경험에서 대기·문의·변경 단계 기록 |
| H-03 | 진료 가능성과 예약 접수를 확신하기 | 예약 시간 표시와 실제 확정 여부를 혼동할 수 있다 | 시연 완료 화면을 보여주고 접수 상태에 관한 이해도 확인 |
| H-04 | 보험 약관을 사전에 파악하기 | 가입 여부만으로 보장 여부를 판단하기 어렵다 | 최근 청구/보장 확인 방식과 어려운 문구 인터뷰 |
| H-05 | 정보 최신성을 신뢰하기 | 휴진일·진료시간·담당자 업데이트 시각/출처가 신뢰에 중요하다 | 정보 신뢰 판단 기준 및 우려 질문 |

## 5. 근거 및 한계

### 외부 자료 (배경 정보)
- 농림축산식품부, 2025-12-22 「전국 동물병원 진료비 현황조사 결과」 발표: 시·군·구별 주요 진료비 최저·최고·평균·중간값을 공개하고 조사 항목을 20종으로 확대함.
- 공식 진료비 조사·공개 시스템: https://www.animalclinicfee.or.kr/
- 이 자료는 지역 단위 진료비 투명성의 배경 근거이지 **특정 보호자의 탐색 불편 빈도나 프지마의 시장 적합성을 입증하는 자료가 아니다.** 개별 병원의 가격·수의사·슬롯을 제공하는 자료도 아니다.

### 현재 확보한 직접 증거
- 기획자의 UI 피드백 및 기능 요구: 병원 찾기 버튼의 직관성, 의료진 선택, 7일 시간표, 기타 입력, 완료/보험 이동, 모바일 레이아웃 개선.
- **실제 보호자 인터뷰: 0명**, 병원 관계자 인터뷰: 0명, 전환율·체류시간 데이터: 없음.
- 사용자 요청은 제품 방향의 유효한 입력이지만 전체 보호자의 의견을 대표하지 않는다.

## 6. 경량 사용자 조사 계획 (제안, 아직 미실시)
- 보호자 **5명 내외**, 가능하면 다양한 반려동물·병원 이용 빈도·보험 경험 포함.
- 동물병원 실무자 **2명 내외**는 파트너 업무 흐름 파악용으로 별도 인터뷰.
- 인터뷰당 15–25분, 비용이 없는 자발적 참여가 기본. 녹음·개인정보 수집은 사전 동의가 있을 때만.
- 진료기록·진단명·계약번호·반려동물 식별 정보는 요청하거나 저장하지 않는다.

### 보호자 인터뷰 질문 (유도 질문 금지)
1. 가장 최근 동물병원을 고른 상황과 이유를 설명해 주실 수 있나요?
2. 후보 병원은 어디에서 어떻게 찾았고, 무엇을 비교했나요?
3. 방문 전 어떤 정보가 확인되지 않아 다시 연락하거나 검색했나요?
4. 예약이 필요한 경우 실제로 어떤 순서로 시간과 담당자를 정했나요?
5. 예약 변경이나 병원 사정으로 일정이 바뀐 경험이 있나요?
6. 보험을 가입했다면 진료 전에 조건을 어떤 방법으로 확인했나요?
7. 병원 정보가 정확하다고 판단한 근거는 무엇이었나요?
8. (시연 후) 예약 화면에서 실제로 병원에 접수됐다고 생각하시나요? 왜 그렇게 이해하셨나요?

### 병원 관계자 질문
1. 예약시간과 의료진별 가능 진료 항목을 누가 어떻게 관리하나요?
2. 전화/온라인 중 예약 접수와 취소는 어떻게 처리하며, 당일 변경은 얼마나 발생하나요?
3. 공개 가능한 진료 정보와 병원 내부 승인·운영 정책의 경계는 어디인가요?
4. 외부 예약 서비스에서 반드시 필요하거나 위험하다고 생각하는 기능은 무엇인가요?

## 7. 검증 기준 (계획값이지 통계적 유의성 기준이 아님)
- 인터뷰 5건에서 반복적으로 나온 문제를 빈도 및 구체적 과거 사례와 함께 요약한다.
- 핵심 작업 3건(① 진료 분야로 병원 찾기 ② 수의사/날짜 선택 ③ 보험 안내 이해)에 대해 시연 테스트 5회를 실시한다.
- 과업 성공률, 걸린 시간, 헤맨 구간, 예약이 실제로 성립했다고 오해한 비율을 기록한다.
- 적은 표본으로 시장 전체의 문제 빈도를 일반화하지 않는다. 정량적 근거가 필요하면 후속 조사 설계.

## 8. 서비스 안전과 위험
- 위험: 가상의 병원/의료진/슬롯을 실제와 오인 → **모든 예약 화면의 시연 안내를 유지.**
- 위험: 보험 지급을 보장하는 듯한 표현 → **약관 확인 항목·참고용 문구만 제공.**
- 위험: 증상으로 응급 상황을 분류/진단 → **진단 기능 범위 제외, 응급 상황에서는 즉시 실제 병원 연락을 권고하는 문구를 향후 설계 검토.**
- 위험: 업데이트되지 않은 운영시간 및 휴진일 → **실제 연동 전 데이터 출처·갱신일·병원 확인 절차 설계 필요.**
