# PJM-010 | 예약 시간 선택 — 주간 캘린더/시간축 UI 설계안 v0.1

- 작성: 2026-11-07
- 상태: **사용자 레퍼런스 접수 / G1 범위 승인 대기 / G2 상세 디자인 미승인 / 구현·배포 안 함**
- 제품: 프지마(PRZIMA) v0.5.2 프로토타입
- 참조: 사용자가 채팅에 첨부한 iPhone 주간 캘린더 스크린샷(화면 구조 참고용)
- 프라이버시: 첨부 이미지에 개인 일정 텍스트가 있으므로 **원본 스크린샷을 공개 저장소에 업로드하지 않음**
- 관련 문서: PJM-002 보호자 여정, PJM-003 PRD, PJM-006 병원 상세보기

## 1. 사용자 요청/해석
"이런식으로 뜨게 해줘" — 기존 카드형 예약 슬롯 대신,
상단의 7일 날짜 목록에서 하루를 선택하고, 아래에서 하루 전체 시간을 **세로 타임라인**으로 내려보며 가능한 예약 시각을 선택하는 형태를 제안받음.

복사 대상은 앱 브랜드가 아닌 **정보 구조와 인터랙션**이다.
- 위: 요일 + 날짜(7일), 선택한 날에 강조된 원형 배경
- 가운데: 'YYYY년 M월 D일 요일' 선택 날짜 타이틀
- 아래: 좌측 시간 레이블 및 가로 눈금선, 이용 가능한 예약 시각은 눈에 띄는 블록으로 표시
- 터치: 날짜 교체, 시간 선택, 예약 확인
- iOS 시스템 UI/개인 일정과 동일하게 보이게 복제하지 않음. 프지마의 기존 크림·딥그린·산세리프를 유지.

## 2. 권장 사용자 흐름 (후보)
가상 병원 선택 → [복수 의료진이면 **담당 수의사 선택** 필수]
→ 상단 **7일 날짜 스트립** → 하단 **하루 세로 타임라인**(가상 슬롯)
→ 이용 가능한 시간을 터치 → 병원/의료진/날짜/시각 요약
→ 진료 목적 선택(기타 직접 입력 지원) → 시연 완료(실제 예약 접수 아님)
→ [선택] 펫보험 알아보기

병원 상세보기 기능이 추가되더라도 이 시간표 컴포넌트는 동일 병원 내에서 재사용하도록 설계한다.
기존 리스트에서 직접 예약하는 경로는 유지한다.

## 4. 화면과 행동 사양

| 영역 | 정의 | 예외 |
| --- | --- | --- |
| 의료진 선택 | 다인 병원에서 필수; 단일 수의사 병원은 해당 담당자 자동 안내 가능 | 의료진 변경 시 선택했던 날짜의 기존 슬롯 무효화 |
| 날짜 선택 | 오늘부터 향후 7일(이동 시 다음 7일)을 노출; 요일·일자·선택 상태 구분 | 지난 날짜 비활성화, 휴진일/예약 불가일은 '없음' 표시 |
| 날짜 헤더 | 선택한 YYYY년 M월 D일 + 요일 표시 | 시간대는 병원 현지(국내 가정) |
| 시간축 | **실제 병원 설정상의 운영시간**으로 범위 결정(시연은 예시 운영시간 사용), 기본 눈금 1시간 | 시간표 전체가 빈 경우 '선택 가능 시간이 없습니다' 안내 |
| 시간 블록 | 예약 가능한 *예시 슬롯*을 30분 단위 블록 등으로 표현하되 실제 슬롯 길이는 설정값에 따름 | 이미 지난 시각·선택 불가 상태는 탭 차단 |
| 선택 피드백 | 탭 시 카드 강조/선택 시각 표기, 하단 '계속' 버튼 활성화 | 슬롯/의료진/날짜가 바뀌면 선택 상태 검증·초기화 |
| 확인 | 기존 목적 선택→예약 시연 완료로 연결 | 실제 접수/예약 확정으로 오해하지 않도록 반복 고지 |
| 화면 레이아웃 | 320/390px 좁은 모바일은 날짜 줄만 가로 스크롤 가능; 시간표는 세로 스크롤 | iOS 화면 하단·상단 UI와 버튼 겹침 방지 |

## 5. 시각 규칙 (G2 제안, 미확정)
- 주간 캘린더: 요일 작은 글씨 + 날짜 큰 숫자, 선택 날짜만 **딥그린 원형** 강조(앱 전체 브랜드와 통일).
- 시간표: 밝은 크림 바탕, 1시간 눈금은 옅은 선, 예약 가능한 시간만 옅은 녹색 카드.
- 선택 완료: 진한 녹색 카드, '선택됨' 보조 텍스트. 사용 불가 시 회색/설명.
- 첫 진입에서는 의미 없는 빈 시간대를 길게 보여주지 않고 **첫 예약 가능한 시간 근처로 스크롤**하거나 '가장 빠른 시간 보기' 제공.
- 예약 시간 블록은 최소 44×44 CSS px 터치 영역(가능한 한); 색 외에 '예약 가능/선택됨' 텍스트로 구분.
- 세로선/분 단위 표현은 예시 데이터에 따라 조절하고, 예약시간이 시간 경계를 걸치는 경우 겹침 없이 렌더링한다.
- 현재 브랜드·사진·그라데이션, 보험/예약 확인 단계는 변경하지 않는다.

## 6. 데이터 모델 후보
```
AvailabilitySlot {
  clinicId: string,
  clinicianId: string | null,
  startsAt: ISO8601 string, // 날짜+시각, 시간대 명시
  endsAt: ISO8601 string,
  status: "available" | "unavailable",
  source: "synthetic-demo"    // 운영 전에는 실제 데이터 금지
}
BookingDraft {
  clinicId: string,
  clinicianId: string | null,
  selectedDate: YYYY-MM-DD,
  selectedSlotId: string | null,
  reasonType: string,
  reasonOtherText?: string
}
```
중복 슬롯, 의료진 중복 예약, 휴진일, 업무시간 밖 슬롯 등 검증은 후속 데이터/기술 설계에서 해결해야 한다.

## 7. Acceptance Criteria (개발 승인 후 테스트)

- [ ] AC-CAL-01: 7개의 요일/날짜가 한 묶음으로 표시되고 선택 날짜가 시각적·접근성적으로 명확하다.
- [ ] AC-CAL-02: 날짜를 바꾸면 **그 날짜의** 시간축/가상 예약 슬롯만 표시된다. 다른 날짜 선택은 반영되지 않는다.
- [ ] AC-CAL-03: 선택된 수의사에 연결된 예약 가능 슬롯만 노출된다; 복수 의료진 병원에서 선생님 미선택 시 예약 확정할 수 없다.
- [ ] AC-CAL-04: 가상 슬롯을 누르면 '선택된 날짜·의료진·시각'이 확인된다. 비활성/지난 슬롯은 선택할 수 없다.
- [ ] AC-CAL-05: 예약 가능한 시간이 없는 날에는 빈 상태 안내를 하고 사용자에게 다음 날짜/의료진 선택 경로를 제공한다.
- [ ] AC-CAL-06: 의료진 변경, 날짜 변경, 모드 변경 시 이전 선택이 잘못 유지되지 않는다.
- [ ] AC-CAL-07: 320/390/768/1440px에서 날짜/시간/하단 버튼이 겹치지 않고 접근 가능; 확대/키보드/스크린리더 레이블 확인.
- [ ] AC-CAL-08: 기존 기타 입력·시연 완료·병원 사정에 따른 취소 가능 문구·보험 수동 이동 유지.
- [ ] AC-CAL-09: 현재 사용되는 슬롯을 '실제 가능'이라고 표현하지 않고 가상 데이터 고지 유지.
