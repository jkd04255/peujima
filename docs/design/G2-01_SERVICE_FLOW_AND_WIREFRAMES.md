# PRZIMA G2-01 — 실제 병원 탐색 / 가상 예약 / 보험 안내 통합 UX 설계 검토안 v0.1

- 상태: **제안 / G2 검토 대기 / 구현 미승인**
- 상위 문서: `docs/design/G2-00_PRODUCT_BASELINE_AUDIT.md`
- 실제 사용자 인터뷰·화면별 신규 실기기 테스트를 수행한 결과가 아닌 **현행 코드와 승인된 기준선에 근거한 설계안**.
- 기준: `main 37e8ed8db0e181d34a02aeff78217b5276ba83b1`, `pjm013-navigation.js`, PJM-011, PJM-012, PJM-020/031/032.
- 이 문서는 현행 제품을 설명하고 추후 UX의 승인 기준을 제시합니다. UI·카피 변경이 실제 배포됐다는 뜻이 아닙니다.

## 1. 사용자 문제 / 디자인 목표

보호자는 “내 주변 실제 병원을 찾는 것”과 “가상의 예약을 체험하는 것”, “보험/진료비 정보를 이해하는 것”을 짧은 시간에 구별해야 합니다. 특정 카드나 안내가 실예약 기능처럼 보이거나, 보험 참고 금액이 개인의 지급액처럼 보이면 안 됩니다.

목표는 **한 화면에서 핵심 행동 하나가 선명하고, 시연의 범위가 분명하고, 다음 화면을 예측할 수 있는 정보구조**입니다.

- 기존 사진·3모드 브랜드 및 색상·서체·카드·CTA 문자열을 먼저 보존합니다.
- 화면마다 동일한 거대 히어로, 중복 액션, 상단 설명을 추가하지 않습니다.
- G2-02에서 화면별 실제 렌더링을 확인하기 전 무단 색/간격/텍스트 수정하지 않습니다.

## 2. 정보구조(IA) — 현행 경로에 맞춘 검토 기준

```text
PRZIMA
├── 홈 (#home)
│   ├── 지역 입력/검색 ──────────────> 주변 병원 (#nearby) [실제 카카오 장소]
│   ├── 내 위치로 찾기 ─────────────> 주변 병원 (#nearby) [명시적 GPS 요청]
│   ├── 실제 병원: 병원 찾기 ───────> 주변 병원 (#nearby)
│   ├── 가상 체험: 예약 체험 ───────> 진료과·예약 (#clinics)
│   ├── 정보 안내: 펫보험 ─────────> 펫보험 (#insurance)
│   └── 진료 분야 ─────────────────> 진료과·예약 (#clinics) [가상 필터]
├── 주변 병원 (#nearby)
│   ├── 실제 지도 + 검색 결과 + 외부 상세
│   ├── 권한 거부/검색 실패/결과 없음/키 오류 처리
│   └── 실제 예약하기 / 의료진 슬롯 연동 없음
├── 진료과·예약 (#clinics)
│   └── 가상 병원 목록 → 선택 병원 상세 → 예약하기 → 의료진
│       → 7일 날짜/세로 시간표 → 선택 확인 → 시연 완료
│       └── 필요 시 별도 펫보험 안내 이동(자동 전환 금지)
└── 펫보험 (#insurance)
    └── 보험 상품 + 진료항목 → 일반 보장조건/진료비 참고 범위
        → 필요한 경우 하단 상세 출처/면책 확인
```

## 3. 모바일 핵심 화면 와이어프레임 (320 / 390px)

아래는 **구조 확인용 텍스트 도식**이지 새 사진 또는 확정된 픽셀 렌더가 아닙니다.

### A. 홈 — 하나의 검색 목표, 서로 다른 서비스 의미

```text
┌──────────────────────────────┐
│ [프지마 브랜드] [전체 강아지 고양이] │
├──────────────────────────────┤
│ [기존 반려동물 사진/크롭]          │
│ (기존 히어로 배치 유지)            │
├──────────────────────────────┤
│ 동물병원 찾기                     │
│ 지역 검색 [지역명/역 입력] [검색]   │
│ 내 위치로 찾기                    │
│ 위치 확인은 이 버튼을 누를 때 시작 │
├──────────────────────────────┤
│ 실제 병원      │ 가상 체험         │
│ 병원 찾기      │ 예약 체험         │
│ (현행 카드 구조는 유지)           │
│ 정보 안내: 펫보험                │
├──────────────────────────────┤
│ 진료 분야 → 가상 예약 화면        │
├──────────────────────────────┤
│ 홈 | 병원 찾기 | 진료과·예약 | 펫보험 │
└──────────────────────────────┘
```

- 검토 질문: 첫 3초 안에 **'실제 장소 검색' vs '가상 예약'** 구별이 가능한가?
- 홈 검색/위치 버튼은 실제 카카오 장소 탐색으로만 이동; 카드 3개의 시각적 중요도는 기존 승인 디자인을 기본값으로.
- 안내/오류문구는 조작 대상 바로 옆에. 개인정보·위치 오해를 부르는 생략 금지.

### B. 주변 병원 — 실제 장소 정보, 예약 없는 탐색

```text
[지역명 입력]  [검색]  [위치 찾기]
[반경 선택 / 상태 메시지]
[카카오 지도]
[실제 병원 결과 카드: 이름/주소/거리(있는 경우)]
[전화 · 외부 지도 상세]
[현재 결과가 실제 예약 가능 시간은 아님을 구분]
[하단 고정 4탭 메뉴]
```

- GPS: 페이지 진입만으로 요청하지 않는다. 사용자가 내 위치 버튼을 직접 눌러야 요청.
- 오류: 위치 거부 또는 GPS 미지원 → 지역명 수동검색 안내; 결과 0건 → 검색조건 변경 안내; API 키/SDK 미작동 → 허위 병원 목록 금지.
- 실제 지도 결과를 가상 예약 상세로 연결하지 않는다.

### C. 가상 예약 — 행동 순서와 안전 경계

```text
[진료과 / 가상 병원 목록]
  ↓ 병원 선택
[선택 병원 소개 / 지역 / 진료과 / 의료진]
[병원 목록으로]  [예약하기]
  ↓ 예약하기를 눌렀을 때만
[의료진 선택]
[7일 날짜 바]
[세로 시간표 / 빈 시간 안내]
[예약 내용 확인 (시연)]
  ↓
[예약 체험 완료: 실제 병원 접수 아님]
[펫보험 안내로 이동]  [목록 복귀]
```

- 캘린더는 상세 화면의 예약하기 이전에는 노출하지 않는다.
- 의료진·날짜 바꿀 때 선택 슬롯 초기화, 휴진·빈 슬롯 안내, 실예약 아님을 반복 검증.
- 사진과 예약 시간표의 승인된 비율/서체/터치 영역 유지.

### D. 보험·진료비 — 간단 입력, 정보의 신뢰등급 구분

```text
[보험사·상품 선택]
[진료 항목 선택]
[보장 내용 확인하기]
[대표 요약 / 적용의 주요 조건]
[치료별 참고 진료비: 기준/단위/추정 등급]
[더 보기: 상세 보장/면책/근거/출처]
[지급액 확정 아님 · 계약별 차이 명시]
```

- 새 보험 확정 액수 계산기를 만들거나 필수 입력을 늘리지 않는다.
- 공식 전국 항목 중간값 ≠ 개별병원 견적; 공개 사례 구간 ≠ 전국 평균; '예산 추정' ≠ 검증된 통계.
- 보장·특약·면책·보험사 심사 조건은 빠짐없이 유지하며, 세부 출처는 기존 하단 펼침 정책 보존.

## 4. PC 및 태블릿 검토 (768 / 1440px)

- 768px: 기존 반응형 메뉴와 카드/검색 UI 흐름 우선; 터치/키보드 이동 검토.
- 1440px: 현재 데스크톱 상단 4개 서비스 메뉴와 3모드 전환을 유지. 병원 결과·상세·예약에서 사용자가 왼쪽에서 오른쪽, 위에서 아래로 자연스럽게 정보를 읽도록 확인.
- PC에서 별도 메뉴·이중 CTA 또는 모바일 카드의 동일한 장식 반복을 만들지 않는다.
- 좁은 화면에서 고정 메뉴가 보험 페이지 하단 근거/버튼을 가리지 않도록 안전영역·스크롤·키보드 포커스 검토.

## 5. 공통 상태/레이블 설계 원칙

| 이벤트 | 필요한 응답·행동 | 피할 표현 |
| --- | --- | --- |
| GPS 권한 거부 | 사용자가 직접 입력하는 지역검색 제공 | 위치가 항상 자동 수집된다는 암시 |
| 실제 병원 0건 / API 오류 | 조건을 다시 지정하거나 외부 지도 확인 | 가상 병원을 실제 결과로 대체 |
| 가상 병원·의료진 선택 | 예약 체험 표시, 상세로 진입 후 예약 버튼 제공 | 실제 예약 가능·병원 확정 표현 |
| 슬롯 0건 / 변경 | 날짜/의료진 재선택 가능; 기존 선택 초기화 | 선택했던 날짜가 여전히 유효한 듯한 상태 |
| 가상 예약 완료 | **실제 예약 접수 아님**을 명시; 보험은 선택 이동 | 실제 예약 접수 완료 |
| 보험 근거 미확인 | 검증 불충분/계약별 확인 필요를 가독성 있게 표시 | 특정 금액 지급 확정/무조건 보장 |
| 비용 자료 분류 | 공식 중간값·사례 참고·예산 추정의 차이를 표시 | 모든 치료비가 전국 평균이라는 주장 |

- `role=status`/aria-live, focus-visible, 예측 가능한 브라우저 Back/Skip link를 G2 설계 검토에 포함.
- 모든 중요한 상태의 의미를 색상·아이콘만으로 전달하지 않음.
- 실제 위치·계약·병력 같은 개인정보를 새로 저장하지 않음.

## 6. 인수 기준 (검토 가능)

- **G2-01-AC1**: 현행 4개 라우트/3모드와 진입 경로를 실제 코드와 1:1 대조할 수 있다.
- **G2-01-AC2**: 각 화면에서 실제 장소·가상 예약·보험 참고정보가 명확히 다른 작업임을 식별할 수 있다.
- **G2-01-AC3**: 모바일 320/390px와 PC 1440px의 주요 CTA·정보 순서·되돌리기/오류/빈 상태를 설명한다.
- **G2-01-AC4**: 개인정보, 실제 예약, 보험금 확정, 진료비 근거 등급에 관한 필수 고지는 제거하지 않는다.
- **G2-01-AC5**: 기존 핵심 사진·브랜드·색/서체·캘린더·카카오 지도·보험 화면을 임의 변경하지 않는다.
- **G2-01-AC6**: 이 문서의 승인만으로 GitHub Pages 배포 또는 실제 예약 API 연동을 허용하지 않는다.
