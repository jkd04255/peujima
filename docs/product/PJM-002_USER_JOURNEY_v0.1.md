# PJM-002 | 보호자 이용 여정 및 예외 상태 v0.1

- 작성: 2026-11-07
- 상태: G0 반영 / G1 검토 대기 / UX 상세 설계 전
- 기준: 프지마 v0.5.2 정적 시연
- **주의:** 현재 예약 시간·의료진·병원은 합성 데이터다. '완료'는 UI 체험이며 실제 병원 접수를 의미하지 않는다.

## B. 후속 UX 제안 — 병원 상세보기 추가 시

**현재:** 진료과/검색 → 병원 목록 → 리스트 내 의료진/시간표 선택 → 가상 완료 → [선택] 보험 안내

**후보:** 진료과/검색 → 병원 목록 → **병원 상세보기** → 의료진 선택 → 7일 시간표 → 진료 목적 → 가상 완료 → [선택] 보험 안내

- 병원 상세에서 뒤로 가면 직전 검색어·진료과·모드를 유지한다.
- 상세에서 날짜/의료진을 고르면 별도 병원의 가상 시간으로 이동하지 않는다.
- 상세 페이지에서 병원 정보의 실제 인증 또는 실시간 예약 상태를 암시하지 않는다.
- 이 흐름은 **제안**이며 G1(범위), G2(화면) 승인 전에는 구현하지 않는다.

| E-07 | 진료 목적 '기타'인데 설명 없음 | 빈 입력 검증 및 직접 입력 안내 | 현행 |

## D. 실제 예약 서비스를 도입하기 전의 상태 설계(초안, 시연 미구현)
1. 보호자가 요청(Requested)한다.
2. 병원에서 수용(Pending Review) / 거절(Rejected) / 시간 제안(Reschedule Proposed)한다.
3. 양측 확인 후에만 확정(Confirmed)한다.
4. 사후 변경/취소는 주체·시각·사유·통지 기록이 필요하다.

**현재 시연의 완료 화면을 이 상태의 'Confirmed'로 해석하지 않는다.**

## E. 인터뷰 관찰표
- 참여자가 진료과와 병원을 선택하는 과정에서 되돌아가거나 검색을 반복한 횟수
- 수의사 선택 필요 여부를 스스로 발견했는가?
- 7일 슬롯의 예시 성격을 이해했는가?
- 가상 완료 화면을 실제 접수로 오해했는가?
- 보험 안내가 '확정 보장'이 아니라는 점을 이해했는가?
- 중요하게 찾은 정보(거리, 휴무, 진료 분야, 의료진, 가격, 리뷰 등)를 **사후 자유롭게 진술**하게 해 우선순위 검증

## F. G1/G2 전 확인할 질문
1. 병원 상세보기의 최우선 정보는 무엇이어야 할까? (조사 결과 우선)
2. 목록에서 바로 예약하는 현재 흐름을 남길지, 상세를 필수 단계로 둘지?
3. 보험 안내로 이동하는 현재 시연 완료 후 선택적 흐름을 유지할지? (유지 제안)
