# PJM-006 | 첫 개선 후보 — 병원 상세보기 기능 기획서 v0.1

- 작성: 2026-11-07
- 상태: **제안 / G1 범위 미승인 / G2 디자인 미승인 / 미개발**
- 기준선: v0.5.2
- 연결: PJM-001(문제), PJM-002(여정), PJM-003(PRD), Sprint 00 #1

## 1. 사용자 문제
진료과로 병원 후보를 찾은 보호자가 병원별 운영 정보·진료 대상·담당 의료진을 한 번에 비교하기 어려울 수 있다. 리스트의 정보만으로는 예약 결정 근거가 부족한지 실제 사용자 테스트로 확인해야 한다.

## 2. 제안
병원 카드에 **병원 상세보기** 진입 버튼을 추가한다. 선택한 가상 병원의 진료 가능 동물·진료 분야·운영시간 및 휴진일·담당 수의사·7일 예시 시간표를 한 화면에서 구조적으로 확인하고, 그 병원에 대해 기존 예약 시연 흐름으로 이어진다.

**왜 1순위 후보인가?** 현재 병원 탐색과 예약이 이미 시연되므로 그 사이의 정보 신뢰도를 높이는 작은 UX 개선이며, 실제 서버/예약 연동 없이 평가할 수 있다. 다만 사용성 테스트 전 우선순위는 임시.

## 3. 이번 범위 제안
### 포함 (P1)
- 기존 5개 합성 병원 카드에서 상세보기 진입.
- 병원명·종 지원·진료 분야·운영시간/휴진일·가상 수의사(있는 경우) 표시.
- 운영 정보/휴진일이 불명확한 항목에는 '정보 미확인' 표시(임의 데이터로 채우지 않음).
- 상세 보기에서 같은 병원의 기존 7일 예약 타임라인으로 이동.
- 뒤로가기 시 모드·검색어·진료과 필터 유지(브라우저 복원 방식은 G2 기술 설계에서 확정).
- 모바일 우선, PC 화면은 기존 디자인의 확대형; 스크린리더 라벨과 키보드 접근 포함.
- 데모 사실을 눈에 띄게 고지하고 데이터 출처/갱신 표시는 가상으로 오인되지 않게 설명.

### 제외
- 실제 병원의 개인정보·진료기록·실시간 예약/영업 여부.
- 지도 API, 실제 좌표, 길찾기 시간, 위치 허용 요청.
- 검증되지 않은 리뷰/평점, 허구의 의료진 프로필·사진을 실재처럼 표시.
- 개별 병원 진료비/예상비용 생성, 보험 적용 보장.
- 로그인·즐겨찾기 동기화·관리자/병원 계정·DB/예약 서버.
- 기존 예약 흐름 전면 재설계.

## 4. 현행 → 후보 UX
현행: 모드·진료과 선택 → 병원 결과 목록에서 수의사/시간 선택 → 시연 완료 → [선택] 보험

후보: 모드·진료과 선택 → 병원 목록 → **상세보기(선택적)** → 병원 정보 검토 → 같은 병원 수의사/시간 선택 → 시연 완료 → [선택] 보험

상세보기를 필수 단계로 강제하지 않아 기존 '바로 예약' 경로를 보존하는 것이 기본 제안.

## 5. 데이터 구조(설계 초안)
- clinicId: 내부 가상 병원 ID
- displayName: 가상 병원명
- supportedSpecies: dog/cat/other 배열
- specialties: 진료 분야 배열
- openHours: 요일별 표시 문자열 / 미확인 상태
- closedDays: 휴진일·미확인 상태
- clinicians: 가상 의료진 ID, 표시용 이름, 역할
- weeklySlots: 동일 clinicId와 clinicianId에 귀속된 시연용 시간
- dataLabel: '가상 데이터 · 실제 예약 불가' 문구

**주의:** 실제 병원 정보 수집·갱신·게시권한·의료진 동의는 별도 검토 후 결정.

## 6. 인수기준(AC) — 구현 전에 G1/G2 승인 필요
- [ ] AC-01: 모드/진료과/검색어 필터가 적용된 목록에서 특정 병원의 상세보기로 들어가면 **선택한 그 병원**의 데이터만 표시된다.
- [ ] AC-02: 상세 화면에서 병원명·지원 동물·진료과·운영시간/휴진일·의료진을 구분해 볼 수 있고 가상 데이터 안내가 표시된다.
- [ ] AC-03: 미확인 운영정보는 '미확인'으로 보이고 존재하지 않는 실시간 예약 가능성이나 평점을 표시하지 않는다.
- [ ] AC-04: 상세 화면에서 기존 7일 타임라인으로 이동해도 clinicId가 유지되며, 복수 의료진 병원에서는 수의사 선택이 필요하다.
- [ ] AC-05: 뒤로 가면 기존 종 모드·필터·검색어가 유지되고, 모바일 320/390px에서 가로 스크롤이 없다.
- [ ] AC-06: 기존 기타 입력, 예약 확인 화면, 병원 사정에 따른 취소 가능 안내, 수동 보험 안내 이동이 변하지 않는다.
- [ ] AC-07: 키보드 탐색, 명확한 닫기/뒤로 가기, 화면 명칭 등 접근성을 점검한다.

## 7. 위험과 예외
- 병원 데이터 미존재/항목 누락: '미확인' 표시 및 복귀 버튼.
- 등록되지 않은 병원 ID: 안내와 목록 복귀.
- 현재 선택 종과 미지원 병원 불일치: 예약 비활성화 및 안내.
- 상세/예약 전환 중 의료진/슬롯 데이터 바뀜: 해당 선택 초기화.
- 실존 병원 정보로 오해: 화면 상단/예약 단계에 데모 고지 반복.

## 8. UX 디자인 원칙
