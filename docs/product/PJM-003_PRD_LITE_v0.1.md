# PJM-003 | 프지마 요구사항 정의서 (PRD Lite v0.1)

- 작성: 2026-11-07
- 단계: **G0 승인 / G1 요구사항 검토 대기**
- 목표 이용자: 반려동물 보호자; 병원은 향후 제휴 파트너
- 제품 기준선: v0.5.2 / https://jkd04255.github.io/peujima/
- 범위: 현재 시연 기능을 명세화하고 다음 기능의 우선순위를 제안. **이 문서의 작성은 개발·배포 승인이 아님.**
- 관련: PJM-001 사용자 문제 정의, PJM-002 사용자 여정, Sprint 00 #1

## 1. 제품 비전과 핵심 가치
**목표:** 보호자가 반려동물 종류와 필요한 진료 분야를 기준으로 병원을 찾고, 병원의 운영정보·의료진·예시 예약시간을 확인한 뒤, 보험 관련 참고사항을 이해하는 일관된 모바일 우선 경험.

**1차 제품가치:**
1. 적합한 병원 후보를 빠르게 좁히기.
2. 가능한 수의사와 시간을 비교하기.
3. 예약·보험 안내의 불확실성을 숨기지 않고 보여주기.

### 명시적 비목표 (현 단계)
- 증상 분석을 통한 자동 진단·처방·응급 분류
- 실제 병원에 예약 등록/확정/취소 메시지 전송
- 실제 의료진 스케줄, 실제 위치, 실시간 운영시간 확보
- 보험금 지급 확정, 약관에 대한 법적 해석, 청구 대행
- 로그인·결제·의료정보 저장·지도 위치권한 수집·업체 관리자 센터

## 2. 요구사항 우선순위와 상태

우선순위 **P0**: 시연에서도 필수 / **P1**: 이후 추가 후보 / **P2**: 추후 검토.
구현 상태 **현행**은 v0.5.2에 사용자 요청을 반영한 화면/코드가 있음을 뜻하며 완전한 QA 또는 실제 운영 검증을 의미하지 않는다.

## 3. 최소 사용자 스토리
- US-01: 보호자로서 강아지·고양이·전체 모드를 선택해 **해당 동물에게 맞는 결과**를 보고 싶다.
- US-02: 보호자로서 진료 분야를 고르고 **그 분야를 다루는 병원**을 확인하고 싶다.
- US-03: 보호자로서 수의사가 여러 명인 병원의 **담당자별 예약 예시 시간**을 보고 싶다.
- US-04: 보호자로서 진료 목적 선택지에 없으면 **기타로 구체적으로 입력**하고 싶다.
- US-05: 보호자로서 진행 결과를 다른 페이지로 갑자기 보내지 않고 **확인 화면에서 검토**하고 싶다.
- US-06: 보호자로서 이후 보험 조건을 알아볼 수 있지만 **보장 확정으로 오해하지 않는 안내**가 필요하다.
- US-07: 보호자로서 병원 상세 페이지에서 진료 분야·운영/휴진·수의사 정보와 시간표를 한눈에 보고 싶다. (**후속 기능 후보**)

## 4. 인수기준 상세 예시 (검증 가능한 문장)
### AC-01 의료진
- Given 복수 수의사가 있는 가상 병원을 선택했다.
- When 수의사를 선택하지 않았다.
- Then 임의 담당자로 예약 시간을 확정할 수 없다.
- When 특정 수의사를 선택했다.
- Then 그 수의사에게 연결된 예시 예약시간만 나타나야 한다.

### AC-02 7일 시간표
- Given 병원 예약 화면에 들어왔다.
- When 주간 이동을 누른다.
- Then 이동한 7일과 각각의 예시 슬롯 상태를 볼 수 있다.
- Then 예약 가능한 시각이 없는 날에 선택 가능한 시간이 보이지 않는다.

### AC-03 기타 진료 내용
- Given 진료 목적이 '기타(직접 입력)'다.
- When 텍스트를 비워 둔 채 완료하려 한다.
- Then 입력 요청 안내가 나와야 한다.
- When 내용을 작성하고 완료한다.
- Then 완료 확인 화면에 해당 내용이 표시된다.

### AC-04 예약 완료·보험
- Given 사용자가 시연용 예약 과정을 완료했다.
- Then 확인 화면에서 선택 내역과 '실제 병원 접수 아님', 병원 사정에 따른 일정 변경/취소 가능성을 확인할 수 있다.
- Then 보험 안내 페이지로 자동 이동하지 않는다.
- When '이어서 펫보험 알아보기'를 직접 선택한다.
- Then 보험 안내가 열린다.

### AC-05 병원 상세보기 (후속 기능 후보)
- Given 가상 병원 목록에서 병원 상세보기로 진입한다.
- Then 병원명·진료 가능 동물·진료 분야·운영시간/휴진일·의료진이 표시되며 실제 데이터가 아닌 점을 알 수 있다.
- When 그 병원에서 예약 시간표로 이동한다.
- Then 동일 병원의 시간표가 열리고 이전 검색/필터가 의도치 않게 초기화되지 않는다.
- When 데이터가 제공되지 않는다.
- Then 사실처럼 보이는 임의 정보를 생성하지 않고 미확인 상태를 표시한다.

## 5. 비기능 요구사항 (QA 목표; 달성 주장 아님)
- NFR-01: 모바일 320/390/768px와 데스크톱 1440px에서 가로 스크롤·겹침 없는 표시.
- NFR-02: 키보드 포커스, 라벨, 텍스트 대비, 확대 및 모션 감소 설정을 점검한다(WCAG 2.2 참고).
- NFR-03: 검사 가능한 안정적 UI 상태: 결과 없음, 슬롯 없음, 의료진 미선택, 시연 중단, 모달 닫힘, 보험 약관 미확인.
- NFR-04: 이미지 로딩/일시적 오류가 있어도 텍스트·기능 이용이 가능한 폴백.
- NFR-05: 현재 브라우저 데모에서 병원/보험/진료 정보를 외부 서버로 전송하거나 저장하지 않는다.
- NFR-06: 작업마다 이전 v0.5.2 기능 회귀 테스트와 모바일 화면 비교를 기록.

## 6. 성공 지표 (가설 검증용 초기안)
- 태스크 T1: 진료과를 기준으로 병원 후보 1개 선택.
- 태스크 T2: 복수 수의사 병원에서 담당자 선택→7일 중 시간 선택→기타 진료 목적 입력→확인.
- 태스크 T3: 확인 화면에서 '실제 예약 아님'을 정확히 이해하고, 보험 안내로 이동할 수 있는지 판단.
- 프로토타입 테스트 5건에 대해 각 작업 성공/실패, 진행 시간, 막힌 위치, 오해한 표현을 기록한다. 비교 실험·통계적 유의성은 주장하지 않는다.

## 7. G1 검토가 필요한 결정
1. **첫 개선 목표:** 병원 탐색 정보의 신뢰성(병원 상세보기·운영/휴무 표시) 강화가 최우선인지?
2. **보호자 작업 기준:** 상세 페이지를 본 뒤 예약을 진행하는 흐름을 기본으로 할지?
3. **보험 기능 위치:** 예약 후 선택적 단계로 유지할지? (현재 UX 기준 유지 권고)
4. **진료비 정보:** 개별 병원 가격 비교는 당장 제외하고 공식 지역 통계 검토만 추후 작업으로 둘지?
5. **실제 연동:** 별도 사업 검증 및 병원 계약 전에는 계속 금지할지?
